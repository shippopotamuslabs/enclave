Executive Summary

Enclave runs every chat turn through RustLoopInferenceService, which owns the agent loop (Rust agent_core via UniFFI) and, at each model-call boundary, delegates to an inner provider service through inner.completeSingleTurn(...). The inner service is provider-specific — not a single shared class.

Two implementation families share the RustCompatibleInferenceService contract:

• OpenAI-compatible family — OpenRouterInferenceServiceImpl, XaiInferenceServiceImpl, DeepSeekInferenceServiceImpl, ZaiInferenceServiceImpl, and ApiInferenceServiceImpl (OpenAI / generic) all extend BaseOpenAiSdkInferenceService. They deliver context sidecars as separate system messages placed immediately before the live tail anchor (OpenAiCompatibleVolatilePlacement), and replay frozen snapshots via buildMappedBodyWithSidecars.

• Bespoke services — AnthropicInferenceServiceImpl and GoogleInferenceServiceImpl implement RustCompatibleInferenceService directly and prepend sidecars into the latest user message; LlamaInferenceServiceImpl (local GGUF) injects sidecars into the last user message inside [context]…[/context] markers and tracks a native KV-cache continuation instead of an append-only log.

Stable prefix = prepended system prompt + full tools[] array (schemas unchanged; tool_choice toggles auto/none). Volatile tail = context-management sidecars (state ledger, tool/file indexes, references, cache hints). For the OpenAI family these are system messages just before the live tail anchor — never pinned to wire index 1.

Freeze/replay (OpenAI family): after each completeSingleTurn, live sidecar text is snapshotted via endTurnFreezeSidecar(text, mappedInsertIndex); later calls replay frozen snapshots at the same mapped index. Within a tool loop, prefix bytes stay stable (AOC_22: clearCount=0).

Cross-turn risk: committed transcripts drop engine-internal rows (agent_tool_budget, etc.), but the append-only sync may have counted them during turn 1 → turn-2 rehydration is shorter → compaction_shorter_array clears frozen sidecars. Rust appends budget as a synthetic AgentRole::Tool row (agent_tool_budget.rs:151-177) specifically to avoid in-place tool-result mutation.

Timestamps live in USER message bodies ([Metadata: Sent at …]), not in frozen sidecars — each new user message changes the volatile tail and breaks cache for bytes after the prior stable prefix.

Append-only reset differs by family

At the start of each sendPrompt, RustLoopInferenceService calls inner.resetAppendOnlyForNewPrompt(). For the OpenAI family this is a no-op (BaseOpenAiSdkInferenceService.kt:302), so frozen PR/SC snapshots persist across user turns (keyed by chatId). For Anthropic and Google it invalidates the context, giving each new user prompt a fresh append-only log. Dispatch is exhaustive in AppendOnlyCompactionInvalidation.kt.

Cache Prefix Stability Analysis

Stable within tool loop (OpenAI family): SYS + tools schemas + messages prefix through last frozen snapshot + committed transcript. Proven: AOC_03, AOC_18, AOC_22.

Intentionally volatile: SC* live tail, new tool results, budget B, tool_choice parameter.

Accumulation cost: O(turns) sidecar system messages (accepted in v1).

Index semantics matter: sidecars pin to mappedInsertIndex, not wire[1]. AOC_12, AOC_19 enforce this.

Other families: Anthropic uses ephemeral cache_control breakpoints at the stable history tail; Google caches the stable prefix as CachedContent and sends only the delta; Llama reuses the native KV cache when the rendered prefix matches (kvContinuationValid).

Spec drift noted

  • Older caching spec says sidecars sit "at end of history immediately preceding latest user" — superseded for the OpenAI family by the tail-anchor + append-only design.
  • resetAppendOnlyForNewPrompt() is a no-op (Unit) for the OpenAI family — append-only persists across sendPrompt until closeSession; Anthropic/Google reset it. BaseOpenAiSdkInferenceService.kt:302
